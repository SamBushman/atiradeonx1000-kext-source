# Full evaluation of the repository HEAD (whole stack; stock is the reference, not the standard)

**Pass criteria (user decision, Nov 6): the rebuilt stack is NOT required to match stock.** It deliberately fixes stock bugs (#123 #125 #142 #144 #146 #152 #179 #214 #218 #219 in the kext, #224-#226 and others in the userspace images), so bit-for-bit or output-for-output parity is no longer the verdict. A run passes when:
1. **Features:** every self-checking test (the GL feature suite against the spec formulas, the userspace behavioural tests, the T3 protocol checks, the consumer scenarios, the soak) passes on the rebuilt arm on its own terms.
2. **No regression:** nothing that passed in the last recorded rebuilt run fails now (difftest FAIL list, GL suite, T3 summary, perf), whatever stock does. A new failure is a defect: file it (`rebuilt-kext-defect`) and fix it before continuing.
3. **Performance: equal or better than stock (user goal, Nov 6).** Stock stays the performance reference for every perf measurement (Phases 1-3, 9). Faster is fine; slower than stock beyond measurement noise on any metric is a defect (`rebuilt-kext-defect`, investigate with `component-cost-profiling`, fix before continuing) - not a "noise" shrug and not excused by the intended fixes unless a fix's own cost is shown to be the cause and the trade is brought to the user.
4. **Differences from stock are classified, not failed:** every difference the comparison scripts print is either an intended fix (named issue / README row) or unexplained; an unexplained one is investigated as a possible defect, and it becomes an issue only if a test's own criterion or a regression check shows harm.
Where this runbook says "IDENTICAL to stock" below, read it as "report the differences and classify them" unless the line says the check proves the machine state (the stock-boot baselines).

## Rules that apply to every phase
- Hot-swap only (`sh ~/rung3/swap.sh $K`, then `cd $S && sh Tools/issue157_unstick_hotswap/unstick_hotswap_vram.sh`). **No boot-time install until every other phase passes** (Phase 9 needs an explicit go-ahead).
- **Never hot-swap back to stock after client activity** (#179 panics): each "side" of a consumer test starts from a fresh boot. Plan the order so that stock work happens first on a boot, then swap to rebuilt, then reboot.
- Precheck before each phase: `ssh G5 'ps auxww | egrep -i "godot|soak|crashdump"'` (a `Z` crashdump zombie is normal) and `kextstat | grep ATIRadeon`.
- Watchdog on the dev machine for every long phase: `Tools/stability_watch.sh -l ~/g5logs/final_eval/watch_<phase>.tsv G5 &`. After a hang/panic: power-cycle, pull `/Library/Logs/panic.log` (diff the body, not the mtime), `diskutil verifyVolume` on every volume, then continue.
- Every divergence from stock is a NEW issue (label `rebuilt-kext-defect`), never a reopened one. A stock-only misbehaviour is `stock-driver-bug`.
- **Export the environment in the same Bash call as the script:** `REBUILT_DIR=kext_build_<sha> STOCK_DIR=stockkext SRC=src_<sha> KEXT=kext_build_<sha>` (and, for the U / KU arms, the userspace variables of the arm: `GLD_REDIRECT_FROM=ATIRadeonX1000GLDriver GLD_REDIRECT_TO=<U>/gld_link/ATIRadeonX1000GLDriver_renamed DYLD_INSERT_LIBRARIES=<S>/Tools/userspace/gld_redirect.dylib DYLD_LIBRARY_PATH=<libGL and libGLProgrammability image dir>`). The scripts default to `kext_build_fix`, which is the wrong tip (a sweep once started that way).
- **The watchdog dies when the G5 reboots.** For reboot-heavy phases run it in a restart loop (`while :; do sh Tools/stability_watch.sh -i 20 -d 3000 -l ...watch_<phase>_$n.tsv G5; sleep 15; done`), started with `setsid nohup ... </dev/null &`.
- **A reboot can take up to ~10 min** (SonnetSATA card initialisation); "No route to host" for several minutes is not by itself a hang. Ping first; power-cycle only after ~15 min of silence. After every reboot check Test HD is mounted, `grep -c "Failed OOB" /var/log/system.log` and `panic.log` size. A stall can also recover on its own (#190).
- Start long jobs detached (`setsid nohup ... </dev/null >log 2>&1 &`); a foreground ssh/pipe keeps the tool call open.
- The shared 4K monitor can re-handshake (display flips 1920x1080@60 -> 3840x2160@30; the `hwup_sampler` log shows the flap). It stops a soak (parity diff on display info). It is environmental, not a driver defect: restore with the unstick script, move the log aside, restart. Above 1080p the DVI-to-HDMI link needs more than 165 MHz (single-link limit); the monitor EDID itself advertises 1440p60 and 4K30.
- **`stability_watch.sh` stops after 3600 s by default (it then prints `OK`): pass `-d <seconds longer than the phase>`** (soak: `-d 14900`), or restart it in a loop. A watchdog that quietly ended is a gap in the evidence: disclose it in the report. For T3 use `Tools/t3_watch_loop.sh OUTDIR`.
- Tiger has no `timeout` / `setsid` / `pkill`; start G5-side jobs with `(nohup ... > log 2>&1 < /dev/null &)` and kill with `kill <pid>` / `killall <name>`. Dev-side detached jobs use `setsid nohup ... < /dev/null &`.
- After every push fast-forward the G5 clone (`/Volumes/Test HD/atiradeonx1000-kext-source-current`; the G5 has no GitHub credentials): `git bundle create x.bundle main --not <old sha>` on the dev machine, `scp`, then `git fetch ~/rung3/x.bundle main:refs/remotes/origin/main (the bundle holds the ref `main`, not HEAD: `HEAD:` fails with "couldn't find remote ref HEAD") && git merge --ff-only origin/main` on the G5 (`/usr/local/bin/git`), and check HEAD == origin before a live run. `src_<sha>` trees and `srchead` on the G5 are snapshots, not clones.
- Record a deviation the moment it happens (aborted attempt, watchdog gap, false hang, a run done with the wrong environment) in the evidence directory's `SUMMARY.md`; every one goes into the final report.
- Not safe, never run: broad-fuzz IOConnectMethod calls, kernel memory scans, `glstress`/window fastclear modes, system sleep (#180), the `*_inject` T3 tests.

## Lessons that cost time (check these before blaming the driver)
- **Hot-swapped stock is not a clean control for DVD Player**: it is wedged by the stock composite-completion-fence defect #142 (frame overlay stuck at 0, one `doIDCT` per ~5.2 s) while the rebuilt kext, which has the #142 fix, decodes in real time and then stops at the end of the one-title test disc (#234, closed not-planned). The per-second `dvd=1` watch only says the DVD user client is open: judge a DVD run by the decoded-frame overlay in the screenshots or by counting selector-18 calls in the `iokit_record_va` log (the recorder log is opened O_APPEND: delete it before each run).
- **A bug that only shows on real traffic**: a Ghidra-derived body that drops a return value (`int f(){...return;}`) passes every test that never runs the caller (#233). `Tools/userspace/lost_return_audit.py` plus the corrected fnfuzz RETUSED scan are the gate (Phase 0); on a new black-video / crash-in-VA symptom run `Tools/phase4_dvd_bisect.sh` (variants VA / GL / GA, one fresh boot each) to find which single rebuilt component causes it.
- **A workload started over ssh runs stock userspace** (see Image sets). **A watchdog without `-d` ends after an hour.** A runner's HANG verdict can be a network drop (Phase 6).
- **Timed runs never carry `GLD_REDIRECT_LOG`** (#232). The stock uninitialised-context malloc (#232) and heap shifts change immediate-mode timings by 6-10 %; compare like with like.
- **By-hand WindowServer relaunch loses the race** against launchd's own respawn; use the launchd environment route (`ku_env.sh`).
- **Never run**: broad IOConnect fuzzing, `/dev/kmem` scans, anything on an already-wedged GPU (just `reboot -q`), unloading hot-swapped stock after client activity (#179/#190: one DVD side per boot).
- G5 reboot timing, Test HD mount, Tiger vs Leopard volumes and credential-free pushes: see Rules above and the `g5-repo-management` / `tiger-ssh` skills.
