# Consumer-application runs, stock vs rebuilt (2026-10-15, #45 gap closing)

All automated (no person at the console): the G5's own Aqua session is driven with `open -a Terminal x.command`, `open -a`, synthetic mouse (`Tools/gui_input.c`) and screenshots. Hot-swap unless stated. Rebuilt = `95edbd2` binary md5 `2de86c49...` throughout.

## Godot game, real GL application frame rate (`../perf/godot_fps_20261015/`)
`Tools/godot_fps_compare.sh`: stock/rebuilt interleaved x3, 90 s each, Godot game under `Tools/userspace/opcode_recorder.c` (rebuilt on the G5: the 2026-10-03 copy lacked the FLUSH `t_us` field), `Tools/frame_rate_from_log.py`. GL flushes in 90 s: stock 10802 / 10798 / 10858, rebuilt 10815 / 10813 / 10825 (about 120 per second on both, spread 0.5 %; no crash, no panic). Per-run median derived fps 101-112 stock, 112-150 rebuilt (one 149.5 outlier), p10 frame time 1.51-1.52 ms and p90 15.2 ms on every run of both: the frame-time distribution is the same.
(The 2026-10-04 baseline of 60.6 fps / 59 flushes per second was a different run condition; compare only within this table.)

## Generated DVD disc (`dvd_disc*`)
A 30 s NTSC DVD-Video disc was authored (`Tools/userspace/va_capture/author_video_ts.sh` with dvdauthor built from source, test pattern with a burned-in timecode and frame counter), wrapped as a UDF/ISO image (`hdiutil makehybrid`) and mounted on the G5; DVD Player plays it (a mouse click answers its "previously viewed disc" dialog).
* **Boot-time stock driver:** plays in real time (frame 519 at 17.317 s = 29.97 fps), finishes and returns to black. DVD contexts opened: 0 (the software decode path, as established in `Tools/userspace/va_capture/README.md`).
* **Hot-swapped, stock AND rebuilt:** DVD Player shows the first frame and never advances (timecode 0, frame 0, at +30 s and +65 s). The four screenshots (stock hot-swap 30 s / 65 s, rebuilt hot-swap 30 s / 65 s) are **byte-identical** (md5 5c96c258...). This matches the earlier finding that DVD readiness is a boot-time property that a hot-swap does not reproduce, so disc playback can only be compared with the rebuilt kext as the BOOT-TIME driver (not done; that is the boot-time test, deliberately last).
* No panic or hang with rebuilt disc playback from a fresh boot. Hot-swapped stock then unloaded after DVD Player use panicked in `stop()` (#179, `stock-driver-bug`; `Tests/baseline/panics/`): never swap after DVD Player use, reboot between sides.

## Installed-application sweep (`app_sweep/`, `app_sweep_stockhotswap/`, `motion_repeat/`, `motion_click/`)
`Tools/sweep_fresh_boots.sh` + `Tools/app_sweep.sh`: each side from a FRESH BOOT (boot-time stock with no swap, then rebuilt hot-swapped over the clean boot; never swap after client use, #179). 9 applications, 30-40 s each, screenshot + process/kernel-health/CrashReporter evidence:
* **All 9 launched, ran (still alive at the end), quit cleanly, with no new crash log and no panic, on both sides**: Srb2mac, Half-Life (SDL2), Unreal Tournament 2004, Aquaria, VVVVVV, Marathon, Motion, Quartz Composer, Godot. Rendered screens of the seven games/apps that reach their own UI look the same on both sides (side-by-side montage reviewed; animated content differs only in phase). The games change the display mode (e.g. 640x480) and restore it: display mode changes with the rebuilt kext are exercised too.
* **Quartz Composer** ("Unsupported configuration ... requires ... ATI AGP RADEON ... 16 MB VRAM") and **Motion** ("Minimum System Checks: requires a Quartz Extreme capable video card"): work on the boot-time stock driver, but show the same error on a **hot-swapped stock** kernel (control, `app_sweep_stockhotswap/`, `motion_click/2_stock`) and on the **hot-swapped rebuilt** kernel (`motion_click/3_rebuilt`): identical dialog text. So this is a hot-swap artifact (like the DVD readiness one): their capability check cannot pass on any hot-swapped accelerator; the real comparison needs the rebuilt kext as the boot-time driver. (Motion also shows a first-run registration dialog before the check on some runs: `motion_repeat/` runs all show it; `motion_click/` dismisses it with a scripted click.)

## QuickTime Player and VLC under the passive IOKit recorder (`video2/`, `video3_qt_stockhotswap/`)
`Tools/video_fresh_boots.sh`: each side from a fresh boot, 2 repeats, mid/end screenshots, recorder log counts.
* **VLC** (DVD VOB): the test pattern is on screen on both sides; recorder PRE-line counts 2465/2541 (boot-time stock) vs 2453/2428 (rebuilt hot-swap); no panic, VLC quit handled by the force-kill fallback.
* **QuickTime Player** (MPEG-2 file): reproducibly different between boot-time stock (black video area, 90 recorded kext calls, 2/2 repeats) and rebuilt hot-swap (white video area, 15 calls, 2/2). **Control: stock hot-swapped (2 repeats, fresh boots) = white video area and 15 calls, identical to rebuilt hot-swap** -> hot-swap artifact, not a rebuilt-kext difference (same class as the DVD and Motion/Quartz Composer findings: hot-swapped accelerators behave differently from the boot-time one for video/Quartz-capability consumers). Real comparison needs the rebuilt kext as the boot-time driver. (Neither state shows the test pattern in QuickTime: the movie area is black/white in the screenshots; this is the same on stock.)

## Sleep / wake (`display_sleep_boot/`, `display_sleep_rebuilt/`; issue #180)
* **System sleep hangs the G5 on the boot-time stock stack (2 of 2)**: `Finder > sleep` (Tiger's `pmset` has no `sleepnow`), once with a Wake-on-LAN packet (the dev machine is on Wi-Fi: no wake) and once with `pmset schedule wake`: display off, fans on, no network, no log lines after the sleep, no panic record, power-cycle needed. Not a rebuilt-kext test: stock fails it, the accelerator's role is not isolated (third-party SonnetSATA kext also present) -> #180 (spec-completeness). System sleep is excluded from the regimen.
* **Display sleep / wake (framebuffer power states only)**, `Tools/display_sleep_test.sh`: `pmset displaysleep 1`, 85 s idle (IODisplayWrangler `myCurrentState` 0-1 while asleep, 4 when on), wake with a synthetic mouse event, 3 cycles per side: **boot-time stock 3/3 and rebuilt hot-swap 3/3 pass**: wake works, kext stays loaded, `panic.log` unchanged, `parity_test_harness` (87 calls) output identical before and after every cycle.
* **Display mode changes / re-handshake:** exercised by the game sweep (games switch to 640x480 and back on both kexts) and by every unstick (`force_mode_change`); no failures on either side.
