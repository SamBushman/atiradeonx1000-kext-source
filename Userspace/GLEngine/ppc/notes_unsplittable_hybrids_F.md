# Unsplittable hybrid variables (round 2, agent F, parts 042-056)

Each entry lists a variable whose register carries two roles that share a line (or one web) and cannot be split by the row tooling; the name is a joined name listing both roles.

- `_gleTextureMatTransPtrDivW_body`: `fVar17` = `texCoordSInThenROut`. Read as the s coordinate from the vertex slot (+0x80), then overwritten on the line that also reads it (`fVar17 = fVar20 * fVar2 + (fVar19 * fVar16 + (fVar17 * fVar14 + ...))`) with the r output (stored to +0x88).
- `_gleVtxTextureCoordGenEyeSlow`, `_gleVtxTextureCoordGenObjectSlow`, `_gleMultiVtxTextureCoordGenEyeSlow`, `_gleMultiVtxTextureCoordGenObjectSlow`: `param_2` = `vertexStartThenCursor`. The argument is the first vertex record, copied into the loop cursors of the earlier coordinate blocks; the last coordinate block advances the parameter itself by 0x100.
- `_gleGenerateMipmapData`: `iVar7` = `levelRecordThenComponentCount` (level record read once, then overwritten on the reading line by `_gleComponents(format)`); `iVar20` = `srcThenDestInteriorWidth`, `local_c8` = `srcThenDestInteriorHeight`, `local_c4` = `srcThenDestInteriorDepth` (source interior size at the top of the loop, replaced by the generated level's interior size before the filter loops); `param_5` = `lastLevelThenLevelArg` (last level to generate, then overwritten with nextLevel as the level argument of `_gleModifyPluginTextureLevel`).
- `_gleExecuteClippedVertexArray`: `param_3` = `firstThenNextSequentialIndex` (first index / element offset at entry, then the counter filling the generated sequential index array); `iVar18` and `iVar23` = `runElementsThenAdvanceBytes` / `runElementsThenAdvanceBytes2` (element count plus pending run, multiplied in place by indexSize into the byte advance of drawIndices).
- `_gleGetHistogram`: `iVar26` = `binCountThenRemaining` (histogram bin count, then decremented as the reset loop counter).
- `_gleEvalMap1` `puVar4` and `_gleEvalMap2` `iVar13` = `mapDataThenPoints` (map data block; at the tail advanced to the control points of the last 3/4-component map and passed as `points`).
- Held back (not renamed, to keep register allocation identical): `_gleGenerateMipmapData` uVar28 splits and the pointer-walk webs iVar10/iVar16/iVar23..iVar31; `_gleExecuteClippedVertexArray` maskedIndex/rawThenMaskedIndex and lastIndexPosition webs. Their renames changed register allocation in the gate.
- `_gleVAClipPoly` (held back, not renamed: each split changed register allocation in the gate): `bVar3` (andedCodes web / planeBit web), `puVar7` (nextDstPoly web / srcCursor web), `puVar9` (indexCursor web / releasedCursor web), the arrays `local_f0` (second polygon buffer) and `local_a0` (released generated indices), and `uStack0000001c` (stack copy of param_2 forwarded to the hook). `uVar15` web 1 is named `edgeVertexIndex`: it holds the start vertex `*srcCursor` or, in the second branch, the end vertex `srcCursor[1]`.
- `_gleEvalMap1` / `_gleEvalMap2` (held back): the four per-component-count points pointers (`puVar5` web 1, `puVar12`, `puVar13`, `puVar14` / `iVar14` web 1, `iVar15`, `iVar16`, `iVar17`): identical-valued copies of one base pointer, one per component count; naming them (`pointsForSize1..4`, `selectedPoints`) swapped two register initialisations. `iVar9` (ctx+0x4858 value passed back to the hook at ctx+0x4898 / 0x489c) left: role not established.
