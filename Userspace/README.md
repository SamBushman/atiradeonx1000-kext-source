# Userspace binaries - machine-transcribed C corpus

Every function Ghidra finds in each userspace binary of the Tiger X1900 driver stack, transcribed to C that compiles
(gcc 4.0.1 on the Tiger G5, `-w`), one directory per binary/slice:

    Userspace/<Binary>/<arch>/decls.h      prototypes for every function, imports, data symbols, float tables
    Userspace/<Binary>/<arch>/ghidra_c.h   Ghidra's type/intrinsic vocabulary (undefined4, CONCAT44, sync, ...)
    Userspace/<Binary>/<arch>/part_NNN.c   the functions (address order, 60 per file)
    Userspace/<Binary>/<arch>/ledger.tsv   address, size, name, part, status  (the completeness ledger)

Generated by `Tools/userspace/ghidra2c.py` from a `DecompAll.java` dump (Ghidra 12.1.3, decompiler defaults). Function text is
Ghidra's, with only these mechanical rewrites: invented struct/class pointer types -> `unsigned char *`; `x._4_4_` sub-piece
accesses -> typed loads/stores at a byte offset; `stack0x..`/`xStack..` incoming stack slots -> frame-relative loads; numeric
constants Ghidra labels as data addresses inside code (`&DAT_0000271e`) -> literals; labels shared with another function ->
absolute-address tail calls; K&R definitions so mismatched call arities compile.
Names are Ghidra's (`FUN_<addr>` unless the binary exports a symbol). Nothing is skipped: the ledger row count equals the
Ghidra function count minus its thunks/imports.
