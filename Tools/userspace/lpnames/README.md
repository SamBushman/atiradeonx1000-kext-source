# lpnames: helpers used for the libGLProgrammability naming round (lpE)

Run from the repo root. All of them work on `Userspace/<Bin>/ppc` and need the compile gate (`Tools/userspace/verify_names.sh`, G5).

* `orig.py DIR FN [from to]` - print FN with every table rename taken back (Ghidra text), with current-file line numbers.
* `lw2.py DIR FN` - placeholder variables of FN with their def-use webs (`Tools/userspace/find_webs.py`); each web is PLAIN (Ghidra name still there) or ALIAS (a previous row already named it).
* `wf2.py DIR SPEC OUT` - workflow 2: `ren FN old new ev` renames the new-name of an existing row (table + part file; safe for the gate), `web VAR WEBS new tier ev` goes through `emit_webs.py` (only for PLAIN webs). `fn FN` sets the function.
* `rn.py DIR ren|revert|revert-use ...` - change/undo rows together with the part-file text. NOTE revert-use must not touch `return NAME;` lines (fixed).
* `prep.py`, `reset_fn.py` - undo all rows of some variables / reset a function to HEAD (text + rows).
* `chk.py DIR PART` - compare each function's Ghidra-normalised statements with HEAD (catches lost lines such as `return x;` or `goto`).
* `dupdecl.py FILE... [--fix]` - duplicate declarations in a function's declaration block.
* `fixspec.py`, `mk2.py` - spec helpers (HEAD-group aware web names; local rows that turn into `ren` when a row already exists).
* `mkrows.py DIR SPEC` - `FN|old|new|evidence[|TIER]` lines (FN may be a glob) -> whole-function `local` rows; use it only for variables that really have one role.
* `ph.py DIR [FN-glob]` - placeholders left per function (incl. the `pXVar` / `p_VarN` type-derived names); `fshow.py DIR FN...` - current text of functions with the part-file line numbers `rng.py` wants.
* `anchorfix.py DIR FN...` - turns the machine-written `#L` line anchors of FN's `use` rows into regex anchors; run it BEFORE adding rows that declare new names in FN (see pitfalls).
* `gate.sh TAG [BASE]` - full gate with the UNTRUNCATED problem list (verify_names.sh prints only the last 8 lines of split_equiv, which hid MERGE problems).

Pitfalls found (all gate-visible): a new name spanning webs that a HEAD alias keeps apart (x = f(x) lines are lhs/rhs-split in HEAD rows) is a MERGE; `#N` anchors count from the end of the DECL-matching declaration prefix, so a `T * x;` declaration inserted at the top (apply_names.py now writes `T *x;`) shifts them.

Pitfalls found in the lpK round (all gate- or check-visible):
* `#L` anchors count from the end of the declaration block, so every new `T x;` a split adds shifts them: the first apply passes, the NEXT `apply_names.py --check` fails. Run `anchorfix.py` on the function first.
* Never rename a name an earlier row produced with a new `local` row (chain): use `rn.py ren FN OLD NEW` (edits the row and the text). `rn.py ren` on a Ghidra-original name (e.g. `p0`, `this_00`) changes the text without any row - revert it and add a normal row.
* `rng.py` line numbers are part-file lines of the tree it runs in: generate the rows in the tree the rows will be applied to (a merge that adds declarations above shifts every line).
* A split that leaves one use on the old name shows as DATAFLOW / UNINIT: list every line of the variable (`grep -n`) before writing ranges (multi-line `for (...)` headers, `x = f(x)` lines, the malloc after a length computation).
* Fake-struct locals (`local_50[2]`, `local_48`, `local_40[2]` in `TGenericLinker__BuildSymbolTableList`) are addressed relative to each other (`(int)local_40 + i*4 - 8`): the number of 4-byte declarations a split adds changes their relative distance (MERGE of A-slots). Keep the added declaration count even, or leave the function's split count where the gate passes.
* `find_webs` refuses functions with `do ... while( true )` / goto spaghetti ("do without while"); use `rng.py` ranges there.

Pitfalls found in the lpL round:
* `ph.py` now also counts `fparam_N` (FPR parameters), `in_stack_*` (stack argument slots) and `FUN_xxxx` calls/definitions: the older counters (`[a-z]{0,3}Var..|local_..|param_..|in_[a-z0-9]+`) missed all of them because `\b` does not match inside `fparam_1` / `in_stack_ffffff48`, and ignored the capitalised `pTVar` prefix.
* A split that adds or removes declarations shifts the `#N` line anchors of OTHER tables' rows for the same function (names_L2_roles.tsv `OutputBinary`); the first apply passes and the next `--check` errors with "neither X nor Y in the segment". Convert the row's anchor to a regex over the Ghidra line (`orig.py` prints it).
* An FPR scratch (`fparam_N` assigned in several `switch` cases of `_InterpreterEmulateOp` and also forwarded as a stale argument to the texture sampler) is ONE web: it cannot be split; name it after the register (`scratchF2`) and list the roles in the evidence.
* Gate base must be the last GATED commit; a gate of a committed tree against HEAD compares the tree with itself and reports IDENTICAL.

lpO round (hybrid-name elimination):
* `seg.py DIR SPEC` writes `use` rows from FILE-LINE ranges of the current tree (`FN VAR NEW RANGES TIER EVIDENCE`, tab separated; RANGES = comma list of `A`, `A-B`, with `:first=P` / `:last=P`, P = lhs | rhs | oN+M, and `*` for "the rest of the function", which must come last). It resolves the `to` anchor itself (extending over variable-free lines when the next line is not unique) and exits when it cannot.
* `x = f(x)` hybrids are split by part: `first=lhs` / `first=rhs`, and when one line holds several occurrences (`(x = f(x), x == 0)`) with `oN+M` (the Nth and Mth occurrence of the OLD name still left in the line; rows applied earlier in the same function already took theirs, so count what is left). apply_names.py understands the `oN+M` parts in the first/last columns.
* ORDER: `prep.py`/`rn.py revert*` remove declarations, so line numbers shift. Read the numbers from `fshow.py` AFTER the revert and generate the rows before touching the function again. A spec written against the pre-revert numbering silently renames the wrong lines (the gate or `--check` then fails).
* Reverting the rows of a Ghidra variable reverts ALL its webs (`prep.py`) - re-add every web. `rn.py revert-use FN VAR NAME` reverts only the rows with that new name (use this when the variable also carries many other names, e.g. `iVar6`/`iVar11` in CompileNO/_glpDisassemble2Op).
* `reset_fn.py` puts a function back to HEAD (text and rows); `rn.py ren FN OLD NEW` renames ALL rows that carry the applied name OLD: when a name was given to two Ghidra variables (e.g. `vectorMode` for `iVar15` and `iVar10`), `ren` renames both.
* `unuseddecl.py FILE [--fix]` finds declarations of placeholder names nothing uses any more (prep followed by web rows can leave two `int iVar2;`).
* Each Bash call is a new shell: environment variables (`D`, `S`) must be re-exported in every call.
* A gate with base HEAD compares the working tree with the last COMMIT; commit only after the gate, then use that commit as the next base.
Pitfalls found in the lp13 round (splitting the remaining joined names):
* `classwebs.py DIR FN VAR RULES [SPECOUT]` classifies the def-use webs of a Ghidra variable by regexes over their definitions (RULES: `NAME<TAB>REGEX<TAB>EVIDENCE`); fully classified webs go to a spec for `emit_webs.py`, MIXED / unmatched webs are listed and need a hand-written spec line (web numbers). One new name may serve many webs; one new name must not be used for two different Ghidra variables of the same function.
* Apply the names before regenerating line-number rows: a split that adds declarations shifts every file line of the part, so `rng.py`/`mk` line ranges taken before `apply_names.py` ran select the wrong lines (a stale range produced half a split in `TPoolAllocator__allocate`).
* `prep.py DIR FN VAR` removes EVERY row of that Ghidra variable, including rows that gave it other, already correct names (it dropped `nameLen`, `clearIdx`, `argBasicType`, ...). Copy the rows first (`git show HEAD:<table>`) and re-emit all roles, not just the joined one; `prep.py` also edits tables other than yours (e.g. `names_lpD_02.tsv`), so `git status` before committing.
* A web whose line set contains the declaration line (find_webs `web 0` of a loop variable such as `iVar13`) renames `int iVar13;` first; every later row then fails with "no simple declaration of iVar13". Move the row with the declaration regex to the end of the group, or drop it.
* `find_webs` attributes the stale argument of a multi-line `x = f(..., x)` to the web of the lhs: the use on the continuation line belongs to the PREVIOUS definition (`TIntermBinary::promote` switch-case entry: `sizeInBytes`; `fold`: the 2nd argument and `*4` jump offset are the operator offset). Split such a statement with a separate row for the continuation line and take the name from the register's value before the call; check with `-Wuninitialized` (the new name is reported as used uninitialized when the web is wrong).
* The lhs/rhs flag splits `x = f(x)` only where lhs and rhs are separate lines or separated by the first `=`; `if (x == 2 && (x = f(), x == 1))` on one line has the first use inside the lhs part, so it cannot be split.
* Quick check before a gate: copy the part and headers to the G5, `gcc -arch ppc -O1 -Wuninitialized -c PART` and compare the `used uninitialized` warning set with the base's `.warn`; a variable that is new in the list is a bad web. A duplicate `T x;` declaration makes the candidate fail to compile and the gate then reports the part's `cand.dis` as missing (look for `FAIL cand` at the top of the log).
* Gate base = the last GATED commit (never HEAD after committing the tree under test); `gate.sh` reports `VERDICT: IDENTICAL` for a tree compared with itself.
* `dupdecl.py` did not report a duplicate `undefined **name;` declaration that `rn.py ren` left after merging two names into one (lpM13: `error: redeclaration of 'stackTypeTypeNameOverlay' with no linkage`, gate `FAIL cand part_005.c`): grep the function for `^  T *\**NAME;` yourself after a `ren` that makes two rows share a name, and check the top of the gate log for `FAIL cand`.
* Overlapping stack TType temporaries (`stackType` / `stackTypeB` in `arrayErrorCheck`) split cleanly by code region when the later temporary re-initialises every word before reading it; the word whose address is passed on (`&local_120` = base of the second temporary) is rejected by the gate with `ADDRESS-TAKEN split <fn> <frame offset>` and keeps one name.

Pitfalls found in the gS round (GLDriver parts 010-014, lp19):
* `autoweb.py DIR FN RULES.py OUT [--show]` names every web of every placeholder variable from a small python rule module (`name(var, k, defs, lines, ctx)`, optional `whole(var)`, `EVIDENCE`, `VARS`); `--show` prints the classification first. Variables that only occur in the function header (unused `param_N`, `fparam_N`) must be listed in `VARS`. Address-taken variables are skipped (rename them whole with `whole()`).
* The same Ghidra variable on two webs of a multi-line `x = f(..., x, ...)` statement needs the segment split by hand (definition line / continuation line / uses); the gate reports it as DATAFLOW + UNINIT. Look for it whenever a rule names a completed word after a chain of OR-ed partial words.
* Whole-function `local` rows whose evidence says "later reused as ..." (oldWord0, oldWord1, srcNFileField, instr in the ARB emitters) were multi-role misnomers: revert the row (table and text) and name the webs.
* `use` rows are keyed by the Ghidra function name; `emit_webs.py` is given the current name: `sed 's/\tCURRENT\t/\tGHIDRA\t/'` the result.
* Templated function families (same code shape, different constant) can share one web spec: generate the rows for one function and clone them with the other functions' Ghidra names (anchors are regexes over Ghidra's text and carry over).
* A full GLDriver gate takes ~2-3 minutes; the candidate is packaged when the gate starts, so the working tree may be edited while it runs.
* The counters for "placeholders left" must include `iVarS<N>` (staged stack arguments), `iVarSw<N>`, `unaff_*`, `auStack_*`/`uStack_*`/`cStack_*` and `DAT_`-free `FUN_` definitions; the older regex missed them.
Pitfalls and helpers from the GLDriver lp20 round (parts 015-018):
* `specs.py DIR SPEC OUT` runs many functions' web rows in one spec (`@FN name` blocks; `VAR WEBS new tier evidence`; WEBS = `*`, web numbers from `lw2.py`, or `L<file lines>` with an `L`/`R` side suffix for one `x = f(x)` line, e.g. `L6058L` / `L6058R`, file lines as printed by `orig.py`).
* `unname.py DIR FN VAR...` removes every row of VAR (rows under the function's OLD Ghidra name are matched too) and puts VAR back in the text; use it to replace a whole-function hybrid name by web rows. `prep.py`/`rn.py revert` need the table's function name to equal the part file's header name, which fails after a `func` row renamed the function (they then silently do nothing). NEVER pass variables you do not want undone (a blanket `unname.py ... uVar1..uVar6` removed good rows; `reset_fn.py DIR FN` recovers the function from HEAD).
* After `unname.py` or `apply_names.py` removed a name, run `dupdecl.py FILE --fix` and `unuseddecl.py FILE --fix`: the two declaration lines of two former names both become the placeholder and break the compile (gate gT4: redeclaration of uVar2).
* `use` row anchors are matched against Ghidra's text with ALL renames of the function taken back (`iVar7`, `param_1`, not `loopIndex`, `disassembler`); a `to` anchor takes the first later match (no `@N`).
* A split that gives a dead-argument read (a variable forwarded to a call that ignores it) two names can make that read uninitialised on one path (UNINIT 0 -> 3): keep one name.
Helpers added in the GLDriver round gU (fork lp21):
* `webspec.py DIR FN VAR RULES [SPECOUT]` classifies the def-use webs of VAR by regex rules over the right-hand sides of its definitions (RULES: `NAME<TAB>REGEX<TAB>EVIDENCE`; `~NAME` = weak rule, a web with one strong role takes it; `@NAME` = use rule over any line of the web) and writes `seg.py` specs; a web whose two definitions get different names and the second one reads the variable (`x = f(x)`) is split at that line with lhs/rhs. `uniq.py SPEC` makes the names unique per function (suffix 2, 3 ...), also against identifiers already in the function. `shapes.py FN` lists the distinct definition shapes per placeholder variable (use it to write rules); `ppropose.py OUT LO HI` propagates callee parameter names to unnamed params of functions in parts LO..HI (unanimous call sites only).
* `seg.py` accepts a one-line range with `:first=lhs|rhs` / `:last=...` (written as `from` + `+1`).
* Whole-function names that cover many webs of different roles (the old `arena` for `uVar46`) are flaws: `prep.py` undoes them, `webspec.py` redoes the split.
* A name applied by a `local` row and the same name proposed by `webspec.py` for another variable of the function collide: let `uniq_names.py` (lp21's; `uniq.py` is lp19's suffixing tool) see all names or give `local` rows distinct names.
